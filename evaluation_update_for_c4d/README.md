# Prompt Management 页面说明

`prompt_management (1).html` 是一个单页的提示词管理与评估演示页面，核心目标是把「提示词调试」和「批量评估」串成一条完整流程。

## 页面流程

页面默认停留在「提示词调试」。左侧是产品导航，中间是主工作区，右侧是调试输入/输出区。

1. 先在 `prompt content` 中修改提示词。
2. 在右侧填写 `输入`，点击 `运行` 查看即时输出。
3. 如果输入需要重置，可点 `清空`，只清除右侧调试内容，不影响提示词本身。
4. 调试稳定后切到 `批量测试`，上传数据集并启动批量运行。
5. 批量结束后可在 `运行记录` 中查看单次记录或批量记录。

## 核心逻辑

### 1. 提示词调试

这一页用于“改一句就看效果”。

- 左侧展示当前提示词内容。
- 右侧上半部分是用户输入。
- 右侧下半部分是运行结果输出。
- `运行` 触发单次模拟推理。
- `清空` 只重置输入、输出和状态，不会清掉提示词。

### 2. 批量测试

批量测试用于验证提示词在一组样本上的整体表现。

- 先上传数据集。
- 页面展示前 5 条样本预览。
- 点击开始后会生成一条批量运行记录。
- 批量结果支持分页，不会因为当前页数据少而改变表格高度。
- 每条结果都可以点进单条详情，看提示词、输入、输出和执行时间。
- 支持导出 CSV。

### 3. 运行记录

运行记录是整个评估过程的历史入口。

- 单次运行记录展示提示词、输入、输出。
- 批量运行记录展示当前批次的输入输出列表。
- 批量记录点击后先看列表，再进一步进入单条评估详情。

## 关键函数

- `syncDebug()`：同步调试区状态，维护输入示例、版本和输出状态。
- `runSingle()`：执行单次调试，更新输出内容和状态标签。
- `clearSingleDebug()`：清空右侧调试输入和输出。
- `startBatch()`：模拟启动批量测试，并生成运行记录。
- `openBatchRecord()` / `renderBatchPage()`：打开批量结果并渲染分页表格。
- `openBatchItem()`：打开批量中的单条评估详情。
- `openSingleRecord()`：打开单次运行详情。
- `exportCSV()`：导出当前批次结果。

## 数据结构

页面内置了几组 mock 数据：

- `vd`：提示词版本历史。
- `records`：单次运行记录。
- `batches`：批量运行记录。
- `debugSamples`：调试输入示例。

这些数据主要用于演示页面状态流转，不依赖后端接口。

## 设计目的

这个页面的逻辑不是单纯“展示结果”，而是围绕提示词评估流程来组织：

- 调试阶段强调快速修改与即时反馈。
- 批量阶段强调统一验证与结果沉淀。
- 运行记录阶段强调可追溯性和回看能力。
