# 评估平台通用规则规范

## 1. 文档目标

本文档用于统一评估平台页面的通用设计与交互规则，可复用到数据集、评估记录、trace 明细、配置等管理页面。

---

## 2. 页面结构逻辑

1. 页面采用分层信息架构：列表层 -> 详情层 -> 明细层（抽屉/弹窗）。
2. 顶部标题源唯一，避免页面内重复同名标题。
3. 主工作区固定为：工具栏（搜索/新增）-> 主体列表 -> 分页区。
4. 以表格作为主信息容器，卡片仅用于摘要信息（如汇总 bar）。
5. 创建/导入类任务放弹窗；详情浏览类任务放抽屉，保持上下文连续。

---

## 3. 组件交互逻辑

1. 列表整行可点击进入详情（主动作优先）。
2. 行内操作（如详情、删除）放在操作列，并阻止冒泡，避免误触发行跳转。
3. 关键字段冻结：左侧身份列（如 ID、名称）、右侧操作列。
4. 冻结列在横向滚动时必须遮盖后方内容，不能出现“透字/透标签”。
5. 所有列表字段单行显示，超出截断，hover 显示完整内容（tooltip/title）。
6. 搜索默认即时过滤，不增加额外提交动作。
7. 选择联动保持双向同步（预览勾选 <-> 候选区、行选中 <-> 抽屉内容）。
8. 上传导入流程采用“状态替换”策略：上传后隐藏上传区，删除文件后恢复初始状态。

---

## 4. 视觉规范逻辑

1. 整体风格：克制型企业后台，强调秩序感与信息密度。
2. 视觉基调：浅灰背景 + 白色面板 + 细边框 + 轻阴影。
3. 主色（蓝）用于关键动作、选中态、焦点态；危险动作（删除）使用红色语义强调。
4. 状态标签（tag）低饱和轻量化，仅承担分类识别，不抢主信息。
5. 层级通过结构和位置建立，不依赖大面积重色块。
6. 抽屉/弹窗层级高于列表层，视觉上需明确“覆盖关系”。

---

## 5. 状态与行为规范逻辑

1. 默认态：页面首屏可直接执行核心动作（查找、创建、进入详情）。
2. 悬停态：用于提示可交互性和完整内容查看。
3. 选中态：列表选中行与抽屉内容保持同步高亮。
4. 空态：有明确文案（如“暂无匹配数据”“暂未选择 trace”）。
5. 成功态：创建成功后局部更新（通常插入列表首行），不整页刷新。
6. 删除态：删除后局部移除，并保证上下文可持续。
7. 滚动态：表头/冻结列/抽屉层级关系稳定，不出现遮挡异常。

---

## 6. 复用建议（后续页面）

1. 同壳层：导航、标题、工具栏、表格、分页一致化。
2. 同交互：整行点击、冻结列、单行截断+tooltip、局部更新。
3. 同层级：列表 < 抽屉 < 弹窗（含阴影与 z-index 策略）。
4. 同状态：默认/hover/选中/空态/成功态/删除态统一语义。
5. 同动作语义：主动作突出、危险动作克制、二级动作不抢焦点。
